# Audio: HP's Speaker Filter on the DSP, October 23, 2026

Issue #2, step 1 and a first part of step 2 of `docs/audio-tuning-2026-10-17.md`.
Read-only work on HP's calibration database (`acdb_cal4.acdb`, committed
under `boards/hp-omnibook-5-16-bf1xxx/firmware/qcacsp_crd8480_fixvoice_WHQL/`),
the kernel's AudioReach driver and `linux-msm/audioreach-topology`
(`d6bb205`). Not yet run on the laptop.

## The extraction tool

`scripts/linux/acdb-extract.py` reads an AudioReach ACDB:

- `graphs` lists the graph key vectors and their subgraphs (113 here);
- `modules` lists each subgraph's module instances;
- `cal SUBGRAPH` lists a subgraph's calibration rows, and with `--bin` or
  `--m4` writes one row as the records the DSP takes in `APM_CMD_SET_CFG`
  (`<instance, parameter, size, 0>` and the data, 8-byte aligned), with
  `--remap` to move HP's instance IDs to the topology's.

Every speaker subgraph has a single calibration row, without keys.

## What HP's speaker tuning holds

| Path | Module | HP's records | Effect |
|---|---|---|---|
| Deep buffer (stream `0xB0000074`) | Popless EQ (`0x07001045`) | 5 bands at 60, 230, 910, 3600 and 14000 Hz | **flat**: every band at 0 dB |
| Deep buffer (device `0xB0000075`) | SAL limiter (`0x07001010`) | 36-byte limiter configuration | limiter |
| Deep buffer (device `0xB0000075`) | Vendor module `0x0701000D` | `0x0800137B`, 87,396 bytes, and five small parameters | unknown, most likely the main voicing |
| Low latency (`0xB0000011`) | MSIIR (`0x07001014`) | two biquads on L and R, unity pregain | see below |

The MSIIR records decode with `api_msiir.h` (AudioReach engine):
coefficients in Q30 in the order b0, b1, b2, a1, a2. The default
`0x40000000` with shift 2 is unity, so the shift does not scale the gain.
At 48 kHz:

| Frequency | 40 Hz | 100 Hz | 200 Hz | 500 Hz | 1 kHz | 2 kHz | 5 kHz | 10 kHz |
|---|---|---|---|---|---|---|---|---|
| Stage 1 (low shelf) | −14.9 | −12.1 | −4.5 | −0.2 | 0 | 0 | 0 | 0 |
| Stage 2 (wide cut) | −0.4 | −1.9 | −5.1 | −9.0 | −6.3 | −2.7 | −0.5 | −0.1 |
| Total, dB | −15.3 | −14.1 | −9.5 | −9.2 | −6.3 | −2.7 | −0.5 | −0.1 |

That is the usual voicing of small laptop speakers: the bass the drivers
cannot reproduce is cut by 15 dB, and the boxy mid-range around 500 Hz by
9 dB. It only cuts, so it cannot raise the excursion or the level, which
matters while speaker protection does not run on Linux.

## The kernel: a bug in the configuration parser

Topology module configuration (`SND_SOC_AR_TPLG_MODULE_CFG_TYPE`,
`c7ed4c2debfd`) carries its size in bytes, and `audioreach_set_module_config()`
sends that many bytes. `audioreach_get_module_priv_data()` instead
allocated and copied that many `__le32` elements: it read three times the
configuration's length past its end. `upstream/qcom-next/0008` sizes it in
bytes, refuses a configuration that runs past the widget's private data, and
makes the caller check the error. It is an upstream candidate. For this
topology the over-read stays inside the topology file, so `-16` would not
fault, but it is wrong either way.

## The topology variant

`boards/hp-omnibook-5-16-bf1xxx/audio/MAHUA-HP-OmniBook-5-16-bf1xxx-speaker-eq.m4`
is the board topology with one change: the WSA device subgraph runs
LOG → MSIIR → MFC → codec DMA (`subgraph-device-codec-dma-playback-msiir.m4`,
`module_msiir.m4`). The MSIIR is instance `0x6053` and carries HP's four
records (enable, pregain, filter configuration, module enable) as its
module configuration, generated by:

    python3 scripts/linux/acdb-extract.py acdb_cal4.acdb cal b0000011 \
        --iid 422d --remap 422d=6053 --m4 HP_SPEAKER_MSIIR_CFG hp-speaker-msiir-data.m4

It builds with `alsatplg` (11,948 bytes; the plain topology is 11,320) and
the configuration sits in the MSIIR widget's private data. The filter runs
at the graph's fixed 48 kHz, where its coefficients apply.

It applies HP's low-latency filter to all speaker playback. On Windows the
deep-buffer path runs the vendor module instead, which is likely to cut the
same bass and add more. The vendor module stays out: its 87 KB parameter is
larger than an in-band APM packet can reliably carry, and the kernel has no
out-of-band path for topology configuration.

## The test (kernel -17)

`sudo bash install-audio.sh --speaker-eq` installs the variant under the
name the kernel requests; `install-audio.sh` without the option puts the
plain topology back. After a reboot (or reloading the sound card), check
that playback starts (`check-audio.sh`), that the kernel log has no
`APM_CMD_SET_CFG` error for instance `0x6053`, and compare by ear with
Windows. If the DSP refuses the module, the same coefficients can run in a
PipeWire filter chain instead (`bq_raw`), the fallback in step 5 of the
plan.
