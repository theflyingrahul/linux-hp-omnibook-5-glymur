# EC driver review against peer drivers and HP's tables, November 10, 2026

Before the EC series' v2 is sent, it was checked against every EC driver in
linux-next's `drivers/platform/arm64/` (`next-20261105`), the x86 HP driver
(`drivers/platform/x86/hp/hp-wmi.c`), HP's ACPI tables for this laptop
(`IC10`, `ECGE`, `WMID`, `PEP0`), and the Windows devices that handle the
hotkeys. Owner's questions: function-key lock, the Copilot and emoji keys,
and reporting the keyboard backlight level to the desktop as Windows does.

## What the peers do that v2 does not

| Feature | Peers in `drivers/platform/arm64/` | HP's tables | v2 |
|---|---|---|---|
| Modern-standby notice to the EC on suspend/resume | Qualcomm's reference EC (`qcom-hamoa-ec.c`: register `0x23`, 1 enter, 0 exit, IRQ disabled across), ASUS Glymur (`0x23`, 7/8), ThinkPad T14s, Huawei Gaokun | yes, see below | **missing** |
| Fn-lock state | `fn_lock` sysfs attribute in Acer Aspire 1, Huawei Gaokun, Lenovo Yoga Slim 7x Gen 11 (notified on the EC's Fn-lock event) | event `0x88`; state read by `HQEX(0xBD, 0x01)` | **missing** (event ignored) |
| Keyboard backlight level to the desktop | `kbd_backlight` LED with `brightness_hw_changed`: T14s; Yoga Slim 7x and ASUS register the LED without it | events `0x0d`/`0x1d`; level read by `HQEX(0x05, 0xFF)` | done (`platform::kbd_backlight`) |
| Mic-mute and programmable hotkeys | T14s, Yoga Slim 7x | events `0x11` (F9), `0x1e` (F11) | done |
| Fan, thermistors | ASUS, Gaokun, Yoga Slim 7x (hwmon) | | done |
| Event logging | | | none: ignored events leave no trace, so a test cannot see `0x0d` or `0x88` |

`hp-wmi` on x86 HP laptops ignores both the Fn-lock event (`0x21ab`,
`0x121ab`) and the keyboard-backlight event (`HPWMI_BACKLIT_KB_BRIGHTNESS`),
so x86 HP laptops get neither on Linux. The arm64 peers are the precedent.

## HP's suspend sequence (`PEP0._DSM`, Microsoft modern-standby UUID `11e00d56-…`)

| `_DSM` function | HP's AML |
|---|---|
| 3, display off | `HQEX(0x01, 0x81)`: OS flag 1 set (`SCET(1)`) |
| 4, display on | `HQEX(0x01, 0x01)`: flag 1 clear |
| 7, standby entry | `ECGE._DSM` fn 4 → `IC10._DSM` fn 2 → byte `1` to register `0x23`; then `HQEX(0x01, 0x82)`: flag 2 set (`MSET(1)`) |
| 8, standby exit | byte `0` to register `0x23`; then `HQEX(0x01, 0x02)`: flag 2 clear |

Register `0x23` with 1/0 is exactly Qualcomm's reference EC
(`EC_MODERN_STANDBY_CMD`), as HP's fan and thermistor events `0x30–0x38`
already are. On a device-tree boot nothing calls this `_DSM`, so with v2 the
EC is never told the system is asleep. `-20` turns suspend on, so its
suspend test would run without it. What the EC changes in standby (fan,
keyboard backlight, power-LED breathing, wake sources) is not known; Windows
always sends it.

This also settles the flag left open on 2026-10-22: `0x81` is "display off",
clear while the display is on, so the experiment's leaving it clear was the
right awake state.

## Function-key lock

Left Shift+Fn toggles the mode inside the EC, which then raises event
`0x88`. HP's `WMID._WED` answers WMI hotkey `0x21ab` by reading
`HQEX(0xBD, 0x01)` (reply byte 0 = 1 or 0) and hands it to HP's software
(`HPIC0003`, "HP Application Driver", with HP's enabling services), which
draws "Function key mode"/"Action key mode". Flag `0x80` (`APET`) sets the
same mode from the OS (set: media keys; clear: plain F-keys,
`docs/runbook-results-16-2026-10-21.md`).

Not known yet: whether `0xBD/0x01` reads 1 in Fn-lock (F-keys) mode or in
action-key mode, and whether `APET` and Shift+Fn move the same state. Both
need one live check: read, press Shift+Fn, read, and see what F7 sends.

Linux desktops have no Fn-lock OSD (GNOME and KDE draw none for the peers'
`fn_lock` either), so on Linux the attribute plus its notification is the
upstream form; an on-screen notice would be a small userspace helper.

## Keyboard backlight OSD

v2's `platform::kbd_backlight` LED with `LED_BRIGHT_HW_CHANGED` is what
UPower watches (`brightness_hw_changed`): it emits
`BrightnessChangedWithSource(…, "internal")`, and GNOME draws its keyboard
brightness OSD for that source. So the bottom-centre OSD should work, but
only if the EC raises `0x0d`/`0x1d` on F5. That is not shown yet: the
keyboard sends nothing for F5 (`captures/2026-11-05-k18/hotkeys-*.txt`), and
the only time F5 was tested with a working event line (`-18`) the driver
dropped `0x0d` silently. `-13`'s level readings were polled.

GNOME dims the keyboard on idle by writing `brightness`. The LED has no set
callback, and the LED core drops such writes without a message
(`led-core.c`, `set_brightness_delayed_set_brightness`).

## Keys the keyboard sends itself

Not EC events (HP's event dispatch lists only `0x0b`, `0x0d`, `0x11`, `0x1d`,
`0x1e`, `0x30–0x38`, `0x50–0x55`, `0xc0–0xc3` and `0x88`):

- **F2 (emoji):** Meta+Ctrl+Alt+Shift+Space from the HID keyboard. Windows
  binds that chord; on Linux it is a desktop shortcut. A chord cannot be
  remapped to `KEY_EMOJI_PICKER` in hwdb or the kernel.
- **Copilot:** Meta+Shift+F23, Microsoft's prescribed sequence. Also a
  desktop shortcut.

## Added to v2 for `-20` (owner, 2026-11-10)

Items 1–4 are done: v2 (`aa4df031bb` on linux-next) passes `W=1`, sparse,
kernel-doc and `checkpatch --strict`; `check-ec.sh` and `check-suspend.sh`
carry the tests, and runbook steps 4b and 13 ask for them. `HPEC_FN_LOCK_ON`
assumes a reading of 1 means locked; step 4b shows whether to flip it. Item
5 is not done.

1. Suspend/resume in the driver, in HP's order: suspend: flag `0x81`,
   register `0x23` = 1, flag `0x82`, IRQ disabled (as in `qcom-hamoa-ec.c`);
   resume: IRQ enabled, `0x23` = 0, flag `0x02`, flag `0x01`.
2. `fn_lock` attribute: read through `0xBD/0x01`, written through `APET`,
   `sysfs_notify` on event `0x88`. Polarity from the live check above.
3. `dev_dbg` for every EC event, so the runbook can turn it on with
   `dyndbg` and see `0x0d`, `0x1d` and `0x88`.
4. Runbook steps: F5 three times while watching `brightness_hw_changed`
   and the GNOME OSD; Shift+Fn twice while reading `fn_lock` and pressing
   F7; one suspend cycle checking the fan and keyboard backlight.
5. Optional, userspace: GNOME shortcuts for the F2 chord (emoji picker)
   and the Copilot key.
