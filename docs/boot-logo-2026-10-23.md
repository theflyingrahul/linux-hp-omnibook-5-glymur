# The Firmware Boot Logo on a Device-Tree Boot, October 23, 2026

Plymouth on our device-tree boots shows its fallback instead of HP's logo.
Read-only work on HP's BIOS capsule (`BIOS_eFuse_Payload.cap`, BIOS 15.06,
from the Windows driver store; kept in `.work/`), the ACPI tables captured
on 2026-09-14 and plymouth's source (`074cc38`).

## How Windows does it

1. The firmware draws the logo itself, through UEFI's graphics output,
   before any OS runs. Qualcomm's display driver in HP's firmware does it
   ("`Display_Utils_RenderSplashScreen: OEM Logo Successfully Loaded`").
2. It then publishes the ACPI **BGRT** table (Boot Graphics Resource
   Table): the physical address of the image it drew and where it drew it.
   On this laptop: version 1, a bitmap at `0xc17c8018`, drawn at
   x = 900, y = 492 on the 1920 × 1200 panel.
3. Windows Boot Manager reads the BGRT and keeps that image on screen
   while Windows loads, drawing its spinner below it.

Linux does the same on ACPI systems: `drivers/firmware/efi/efi-bgrt.c`
reserves the image's memory and exposes it as `/sys/firmware/acpi/bgrt/`,
which plymouth's `bgrt` theme shows.

## Why a device-tree boot loses it

With a device tree, arm64 Linux does not parse ACPI at all, so nothing
reads the BGRT, and the image sits in boot-services memory that Linux
reuses. There is no device-tree binding for a boot logo: the BGRT exists
only as an ACPI table. A kernel change that parsed this one ACPI table on a
device-tree boot would be possible, but it mixes the two firmware
interfaces, which upstream avoids, so it is not pursued.

## What plymouth does without a BGRT

Plymouth's two-step plugin (`src/plugins/splash/two-step/plugin.c`) loads
`bgrt-fallback.png` from the theme's image directory
(`/usr/share/plymouth/themes/spinner/` for the `bgrt` theme) when
`UseFirmwareBackground` is set and no BGRT is available. It centres the
image horizontally and puts its vertical centre at 38.2 % of the screen
height (Microsoft's boot logo rule), on black.

## The logo

HP's firmware volume (the LZMA stream at `0x6031fa` of the capsule) holds
HP's logo as a 120 × 120 JPEG on black, next to Compaq's and other brands'
for the same firmware. 120 pixels fits the BGRT exactly: centred, it starts
at (1920 − 120) / 2 = 900. Vertically the firmware draws it lower than
plymouth's 38.2 % rule (top at 492, centre at 552).

`bgrt-fallback.png` is therefore 120 × 468, black, with the logo 268 pixels
down. Plymouth places it at y = 1200 × 382 / 1000 − 468 / 2 = 224, which
puts the logo's top at 492, where the firmware drew it, so the hand-over
from the firmware's splash to plymouth does not move the logo.

The image is HP's and stays out of the repository. It is made here from the
capsule, staged with the private USB kit (`boot-logo/`), and installed by
`scripts/linux/glymur-ssd/install-boot-logo.sh`, which diverts a packaged
`bgrt-fallback.png` with `dpkg-divert` instead of overwriting it.
