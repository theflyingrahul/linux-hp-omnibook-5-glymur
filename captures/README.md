# Hardware Captures

This directory is intended for parsed metadata or evidence summaries.

**DO NOT COMMIT RAW OR PRIVATE CAPTURE DIRECTORIES HERE.**
The output generated by `day0-capture.ps1` often contains proprietary Windows drivers, firmware blobs, and unique machine identifiers (serials/UUIDs).

## Workflow
1. Run `day0-capture.ps1` on the target Windows machine.
2. Transfer the capture directory to your Linux development host.
3. Run `scripts/linux/analyze-day0-capture.py --capture /path/to/capture`.
4. Review the generated reports in `analysis/`.
5. Only commit curated, redacted evidence snippets (e.g., hardware IDs) to the repository.

## Logs from the laptop's Linux install

Logs copied from the laptop (`/var/log/glymur/`, journals, `lsblk`, `ip`,
`bluetoothctl`, `pw-dump`) carry identifiers that must not be published:
Wi-Fi MAC and Bluetooth addresses, partition and filesystem UUIDs
(`root=PARTUUID=…`), USB serial numbers, and the Windows volume label
(which is the computer's name). Before committing any such file, run

    scripts/linux/sanitize-capture.sh <file>...

and read the lines it lists at the end. The boot report and `check-usb.sh`
already redact their own output; other logs do not. History was scrubbed
of such identifiers on 2026-10-22.
